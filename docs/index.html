The problem

Handoff eats the week

The idea is the easy part. Turning it into something a PM can review, a designer can trust, and an engineer can ship — accessibly — is where the days disappear. Four things go wrong again and again:

The design-to-code gapA working idea has to be re-drawn in Figma, annotated for accessibility, and re-typed as code — by hand, three times over.
AI that guessesGeneric code assistants invent component names, props, and tokens that don't exist in your system — so the output looks right and breaks on paste.
Accessibility, bolted on lastFocus order, labels, and contrast get added at the end (if at all), so they slip — and fixing them late is expensive.
Drift from the systemOne-off components and hardcoded colours creep in instead of the real library, and the design language quietly erodes.
The through-line Every one of these is a trust problem — you can't trust the output enough to ship it without redoing the work. Cosmo is built to close that gap.
The idea

One agent, real components

Cosmo is a VS Code agent that never works from memory. It reads your real components from live sources, builds the design from genuine instances, checks it against accessibility and content standards, and only then writes the code — pausing for your sign-off between each step.

🧩Real, not guessedComponents, props, and tokens come from live sources. If it can't verify something, it stops instead of inventing it.
♿A11y from frame oneWCAG 2.2 AA and Responsible-AI are applied while it designs and codes — not patched on at the end.
🎛️You stay in controlA review gate after every phase. Approve, or tell it what to change — nothing ships silently.

Under the hood

The plugins that make it real

Figma can't be written to by an API call — the only way to author real component instances is a Figma plugin. Cosmo uses three small ones, so the design is built from your true library rather than redrawn look-alikes.

① key-extractorRuns once inside your published component library and exports a map of every component to its Figma key — the “what exists” list.
② key-testRuns in your working file and checks those keys actually resolve — catching an unpublished or mis-shared library before any real build.
③ build pluginGenerated per design. It drops in real component instances, applies tokens and sample data, and rebuilds cleanly every run.
Why it matters to you Because the design is assembled from genuine instances, what you review in Figma is what the library really produces — and the code step maps to the same verified components. No look-alikes, no surprises on paste.
